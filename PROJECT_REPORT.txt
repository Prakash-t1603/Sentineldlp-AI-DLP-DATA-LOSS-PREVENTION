1. EXECUTIVE SUMMARY & ARCHITECTURAL OVERVIEW
================================================================================

SentinelDLP AI is an enterprise-grade, multi-channel Data Loss Prevention (DLP) 
and User & Entity Behavior Analytics (UEBA) platform. Designed for modern corporate 
enterprises, financial institutions, and regulated environments, the system detects, 
classifies, intercepts, and prevents unauthorized exfiltration of sensitive, 
proprietary, and regulated data across all primary workstation egress vectors:

  1. Removable USB Mass Storage Devices (Watchdog Real-Time Sensor + OS Mounts)
  2. Web Browsers & Cloud Storage (Google Drive, OneDrive, Dropbox, WhatsApp Web)
  3. Corporate Email & Webmail Attachments (Outlook, Gmail, RFC 822 MIME Streams)
  4. Workstation Clipboard & Local Monitored Filesystem Directories
  5. Process Monitoring & Exfiltration Tool Interception (curl, winscp, mega, tor)

The platform enforces a clean architectural separation between the Central DLP 
Server / SOC Dashboard and the distributed Employee Endpoint Agents.

2.3 ENTERPRISE BROWSER EXTENSION (browser_extension/)
--------------------------------------------------------------------------------

  - Clean Content Encoding: Uses `FileReader.readAsDataURL(file)` to extract pure, 
    uncorrupted Base64 byte payloads (`result.split(',')[1]`) for binary images, 
    scanned PDFs, DOCX, XLSX, CSV, and text files without binary string mangling.
  - Local Agent Dispatch: Transmits pre-flight upload payloads to the local endpoint 
    receiver at `http://127.0.0.1:8765/browser-event` (with multi-port failover to 8766-8768 
    and central fallback `http://172.24.143.236:8000/api/dlp/browser-event`).
  - Active DOM Blocking: If policy returns `action: "BLOCK"`, the extension immediately 
    clears the DOM file input element (`inputElement.value = ""`) and displays a 
    real-time warning toast notification to the employee.

3. CORE DLP CAPABILITIES & DETECTION CHANNELS
================================================================================

--------------------------------------------------------------------------------
3.1 REMOVABLE USB STORAGE WATCHDOG & HARDWARE INTERCEPTION
--------------------------------------------------------------------------------
  - Continuously monitors removable storage insertion and mount events.
  - Intercepts file writes targeting USB drive letters (`E:\`, `F:\` on Windows, 
    `/media/*`, `/mnt/*` on Linux).
  - Computes SHA-256 hash, extracts document text, and triggers synchronous AI classification.
  - Critical/High sensitivity transfers trigger instant BLOCK actions, alerting the SOC.

--------------------------------------------------------------------------------
3.2 WEB BROWSER & CLOUD STORAGE EGRESS PROTECTION
--------------------------------------------------------------------------------
  - Monitors high-risk egress websites: Google Drive, OneDrive, SharePoint, Dropbox, 
    Box, WhatsApp Web, Gmail Webmail, Outlook Webmail, WeTransfer, Mega.
  - Zero HTTPS Wire Decryption: Inspects files at the source browser DOM layer before 
    encryption, preserving HTTPS integrity and avoiding invasive root certificates.
  - Synchronous Pre-Flight Scanning: Content is inspected by the Central AI pipeline 
    before the policy engine decides ALLOW, WARN, or BLOCK.

--------------------------------------------------------------------------------
3.3 CORPORATE EMAIL & MIME ATTACHMENT INSPECTION
--------------------------------------------------------------------------------
  - Analyzes RFC 822 MIME email payloads and multipart attachments (.docx, .pdf, .csv, .xlsx).
  - Validates recipient domain whitelists (distinguishes internal vs external emails).
  - Blocks outgoing attachments containing unencrypted PII, financial info, or API secrets.

--------------------------------------------------------------------------------
3.4 WORKSTATION CLIPBOARD & LOCAL FILESYSTEM WATCHER
--------------------------------------------------------------------------------
  - Clipboard Monitor: Detects copy operations containing AWS keys, credentials, or PAN/Aadhaar.
  - Filesystem Watcher: Observes local directories, ignoring `.git`, `node_modules`, `.venv`.

--------------------------------------------------------------------------------
3.5 PROCESS ANOMALY & EXFILTRATION TOOL DETECTION
--------------------------------------------------------------------------------
  - Periodically inspects active processes for illicit exfiltration programs (e.g. `curl`, 
    `wget`, `mega-cmd`, `tor`, `winscp`, `putty`, `filezilla`).
  - Sends high-priority activity and alert records to Central Server upon detection.

--------------------------------------------------------------------------------
3.6 MULTI-FORMAT DOCUMENT CONTENT EXTRACTORS (backend/services/file_analysis_service.py)
--------------------------------------------------------------------------------
SentinelDLP features dedicated content extraction engines for all primary enterprise formats:
  - Spreadsheets (`.xlsx`, `.xls`): Cell-by-cell inspection across sheets and rows with 
    column header mapping (e.g., `Name`, `Employee ID`, `Salary`, `Credit Card`).
  - Word Processing (`.docx`): Extracts body paragraphs, table cells, headers, and footers.
  - Structured CSV / TSV: Auto-detects delimiters and pairs column headers with row values.
  - JSON Data: Recursively flattens nested dictionaries and arrays for credential inspection.
  - Plain Text & Code (`.txt`, `.env`, `.py`, `.sql`, `.key`): Multi-encoding string extraction.
  - Scanned & Vector PDFs (`.pdf`): PyPDF stream extraction with page image OCR fallback.
  - Images (`.png`, `.jpg`, `.jpeg`, `.tiff`, `.bmp`, `.webp`): Multi-tier OCR extraction.
  - 50MB Safety Limit: Hard boundary prevents memory exhaustion on massive files.

4. AI-POWERED INSPECTION, CLASSIFICATION, OCR & NLP PIPELINE
================================================================================

The SentinelDLP AI subsystem (`backend/ai/`) provides a production-grade, centralized
intelligence engine executing exclusively on the Central DLP Server. Endpoint agents
transmit extracted text, metadata, and raw document payloads for deep inspection.

--------------------------------------------------------------------------------
4.1 MULTI-TIER SENSITIVITY CLASSIFICATION
--------------------------------------------------------------------------------
Documents and egress payloads are classified into five discrete sensitivity tiers:
  1. `PUBLIC` (Score: 0.0 - 0.20): Marketing brochures, public press releases, open-source code.
  2. `INTERNAL` (Score: 0.21 - 0.50): Internal wikis, team meeting minutes, general memos.
  3. `CONFIDENTIAL` (Score: 0.51 - 0.75): Financial statements, roadmaps, customer lists.
  4. `RESTRICTED` (Score: 0.76 - 0.90): Source code algorithms, board meeting minutes, employee PII.
  5. `HIGHLY_CONFIDENTIAL` (Score: 0.91 - 1.00): Private keys, database credentials, AWS root tokens, PAN/Aadhaar databases.

Classification is performed via a dual-engine ensemble combining a trained scikit-learn
TF-IDF + LogisticRegression model with heuristic sensitivity boosters based on entity density
and contextual confidentiality indicators.

--------------------------------------------------------------------------------
4.2 ADVANCED 6-CATEGORY ENTITY RECOGNITION (backend/ai/entity_detector.py)
--------------------------------------------------------------------------------
The entity detection engine inspects text for high-risk patterns across 6 major domains:

  1. Financial:
     - Credit Card Numbers: Visa, Mastercard, Amex, Discover, Diners, JCB, RuPay with Luhn Modulo-10 checksum validation.
     - International Bank Account Numbers (IBAN): ISO 13616 format validation.
     - SWIFT / BIC Codes: ISO 9362 international bank identifier recognition.
     - Crypto Wallets: Bitcoin (Legacy 1/3, SegWit bc1) and Ethereum (0x 40-hex) addresses.
     - Bank Account Numbers: Financial account numbers linked to banking keywords.

  2. Identity:
     - Indian Aadhaar Numbers: 12-digit UIDAI format with Dihedral D5 Verhoeff Checksum algorithm.
     - Indian Permanent Account Numbers (PAN): 10-character alphanumeric tax ID format with status validation.
     - US Social Security Numbers (SSN): 9-digit format with area/group rule checks.
     - Passport Numbers: Standard travel identification formats.
     - Driver Licenses: State-issued driver license alphanumeric patterns.

  3. Credentials & Secrets:
     - AWS Access Key IDs (`AKIA[0-9A-Z]{16}`) and AWS Secret Access Keys.
     - RSA / ECDSA / OpenSSH Private Keys (`-----BEGIN RSA PRIVATE KEY-----`).
     - JSON Web Tokens (JWT) and GitHub / GitLab Personal Access Tokens.
     - High-Entropy Strings: Shannon Entropy calculation (entropy > 3.8 bits/char).
     - Database Connection Strings: `postgres://`, `mysql://`, `mongodb://`, `redis://`, `mssql://`.

  4. Personal / PII:
     - Corporate and personal email addresses (filtering out web asset false-positives).
     - International phone numbers (E.164 and localized formats, 10-15 digits).
     - Date of Birth (DOB) and Candidate / Employee Full Names in structured forms.

  5. Corporate & Intellectual Property:
     - Employee Identification Badges (`EMP-XXXXX`, `EMP_XXXXX`).
     - Employee Salaries & Compensation packages (`Salary: $145,000`, `₹18,00,000`, `CTC:`).
     - Merger & Acquisition (M&A) project code names and confidential offering term sheets.
     - Board resolutions, executive compensation, customer pipeline reports.
     - Source Code Secrets: Hardcoded secret keys in code repositories.

  6. Health (HIPAA PHI):
     - Medical Record Numbers (MRN), ICD-10 diagnostic codes, patient prescription records.
     - Health Insurance IDs, Policy Numbers, RxBIN healthcare identifiers.

Safe Redaction & Data Masking:
  All detected sensitive entities are automatically masked (e.g. `XXXX-XXXX-1098` for Aadhaar,
  `4532-****-****-8812` for Credit Cards, `AKIA...MPLE` for AWS keys) in audit logs and SOC views.

--------------------------------------------------------------------------------
4.3 NATURAL LANGUAGE PROCESSING & EXFILTRATION INTENT (backend/ai/nlp_engine.py)
--------------------------------------------------------------------------------
The NLP engine extracts contextual semantic meaning from documents and communications:
  - Confidentiality Markers: Detects headers like "STRICTLY CONFIDENTIAL", "DO NOT DISTRIBUTE",
    "ATTORNEY-CLIENT PRIVILEGED", "PROPRIETARY & TRADE SECRET", "RESTRICTED ACCESS".
  - Exfiltration Intent Patterns: Detects phrases like "sending to my personal email", "backup to usb",
    "bypass firewall", "exporting full database", "leaking company data".
  - Context Window Reinforcement: When sensitive entities appear in proximity to exfiltration intent
    or confidentiality markers, a dynamic 1.25x - 1.50x confidence multiplier is applied.

--------------------------------------------------------------------------------
4.4 MULTI-TIER OPTICAL CHARACTER RECOGNITION (backend/ai/ocr_engine.py)
--------------------------------------------------------------------------------
Visual text extraction features a multi-tiered architecture with graceful fallback:
  - Image Preprocessing: Grayscale conversion, contrast enhancement (1.8x), and sharpening filters.
  - Tier 1: Tesseract OCR with OpenCV / PIL adaptive thresholding.
  - Tier 2: Real image text chunks & EXIF metadata extraction for camera/scanner annotations.
  - Tier 3: Scanned PDF page image extraction: extracts embedded image streams from PDF pages 
    and applies OCR when standard text layers are empty.
  - File Format Support: PDF, DOCX, XLSX, PNG, JPG, JPEG, BMP, TIFF, WEBP, TXT, CSV, JSON, ENV.

--------------------------------------------------------------------------------
4.5 EXPLAINABLE CONFIDENCE ENGINE (backend/ai/confidence.py)
--------------------------------------------------------------------------------
Every DLP scan yields an explainable confidence score (0.0 to 1.0) and human-readable reasoning:
  - Base Model Probability (TF-IDF Scikit-Learn Class Probability)
  - Entity Verification Weight (Validated Luhn/Verhoeff cards and IDs)
  - Contextual Multiplier (Confidentiality markers and exfiltration intent)
  - OCR Transcription Factor (OCR confidence applied when image inspection used)
  - Explainability Trace: Returns an ordered audit trail of contributing factors (e.g. 
    `[Model: RESTRICTED (0.94), Entities: 1 Aadhaar (Verhoeff Validated), OCR: DETECTED (0.95)]`).

--------------------------------------------------------------------------------
4.6 DUAL-PATH INSPECTION PIPELINE (backend/ai/pipeline.py)
--------------------------------------------------------------------------------
To maximize throughput and minimize latency across enterprise fleets:
  - Fast-Path (Cache Hit): SHA-256 content byte hash check against existing classification cache.
    Response latency < 2ms.
  - Slow-Path (Deep Inspection): Full OCR -> NLP -> Entity Regex -> Scikit-Learn Classifier -> 
    Confidence Engine -> UEBA Anomaly Check. Stores hash in cache upon completion.

--------------------------------------------------------------------------------
4.7 50MB SAFETY LIMIT & FAULT-TOLERANT BOUNDARIES
--------------------------------------------------------------------------------
  - Hard limit: `MAX_ANALYSIS_FILE_SIZE = 50 * 1024 * 1024` (50MB).
  - Files exceeding 50MB return status `CONTENT_ANALYSIS_LIMIT_EXCEEDED` and undergo 
    metadata + hash inspection without crashing agent or central server.
  - Degraded OCR / parsing errors return `ANALYSIS_INCOMPLETE` without falsely labeling files as clean.

--------------------------------------------------------------------------------
4.8 OFFLINE MODEL TRAINING & EVALUATION SUBSYSTEM (training/)
--------------------------------------------------------------------------------
Located in `training/`:
  - `training/sample_data.py`: Multi-domain enterprise training corpus covering all 5 sensitivity tiers.
  - `training/train_classifier.py`: Trains TF-IDF vectorizer + LogisticRegression model, evaluated with 
    stratified 5-fold cross validation (100% accuracy, F1=1.00), exporting to `backend/ai/models/`.
  - `training/evaluate.py`: Production benchmark evaluator running 7 adversarial test suites.

5. USER AND ENTITY BEHAVIOR ANALYTICS (UEBA) SUBSYSTEM
================================================================================

The UEBA engine (`backend/ai/ueba.py`) monitors employee activity patterns across time,
channels, and volume to identify insider threats, compromised accounts, and rogue data exfiltration.

--------------------------------------------------------------------------------
5.1 BASELINE PROFILING
--------------------------------------------------------------------------------
For every registered employee, the system maintains a dynamic rolling behavioral profile:
  - Daily Event Moving Average (Mean μ and Standard Deviation σ of event volume)
  - Daily Data Transfer Volume Moving Average (Bytes transferred per 24-hour cycle)
  - Typical Working Hours Matrix: Standard active window (e.g. 08:00 - 19:00 local time)
  - After-Hours Activity Ratio: Baseline percentage of off-hours operations
  - Channel Usage Breakdown: Baseline percentages for USB, Browser, Email, and File operations
  - Common Destination Domains and Removable Drive Serial Identifiers

--------------------------------------------------------------------------------
5.2 Z-SCORE VOLUME ANOMALY DETECTION & PEER GROUP DEVIATIONS
--------------------------------------------------------------------------------
  - Z-Score Volume Anomaly: Computes standard deviations from historical baseline:
      Z = (Current Daily Events - Mean Baseline) / (Standard Deviation + ε)
      * Z > 3.0: High Volume Burst Anomaly (Flagged as anomalous)
      * Z > 5.0: Critical Exfiltration Burst Anomaly (Triggers immediate High/Critical Alert)
  - After-Hours Anomaly: Detects significant bursts of sensitive file transfers occurring 
    outside standard operational hours (20:00 - 06:00).
  - Unusual Removable Storage Anomaly: Flags transfers to newly connected, unapproved USB drives.
  - Department Peer Group Deviation: Compares individual risk score against the departmental average.
    Deviations exceeding 25 points above the departmental baseline trigger peer-group anomaly warnings.

--------------------------------------------------------------------------------
5.3 INSUFFICIENT BASELINE PROTECTION
--------------------------------------------------------------------------------
To eliminate false alarms during employee onboarding, the UEBA engine enforces an
insufficient baseline protection threshold (`total_events_observed < 5`). Newly registered
workstations are marked as `INSUFFICIENT_BASELINE` without fabricating false anomalies.

--------------------------------------------------------------------------------
5.4 ANALYST FEEDBACK & CONTINUOUS MODEL CALIBRATION
--------------------------------------------------------------------------------
SOC analysts can review classifications in real time and submit feedback:
  - Mark False Positives (`is_false_positive=true`) or False Negatives
  - Correct Sensitivity Labels (e.g. adjust `CONFIDENTIAL` to `INTERNAL`)
  - Continuous feedback adjusts model confidence thresholds and triggers retraining.

6. MULTI-FACTOR COMPOSITE RISK ENGINE & POLICY GOVERNANCE MATRIX
================================================================================

Composite Multi-Factor Risk Formula:
  Raw Risk = [ (Sensitivity * 0.40) + (Confidence * 100 * 0.25) + (UEBA Anomaly * 100 * 0.20) ]
             * Channel Multiplier + Destination Add-on + Temporal Add-on

Where:
  - Sensitivity Score (0 - 100): Base Tier Score + min(30.0, Entity Count * 5.0)
  - Confidence Score (0.0 - 1.0): Hybrid confidence from ML, Entity validation, NLP.
  - UEBA Anomaly (0.0 - 1.0): Normalized behavioral anomaly score.
  - Channel Multiplier:
      * USB / External Removable Drive: 1.30x
      * Web Browser Upload / Cloud:    1.20x
      * Corporate Email Attachment:    1.15x
      * Clipboard Transfer:            1.10x
      * Local File Operation:          1.00x
  - Destination Risk Add-on:
      * External Webmail / Cloud (+10.0 points): Gmail, Google Drive, Dropbox, 
        OneDrive, WeTransfer, Mega.nz, WhatsApp Web.
      * Internal Network (0.0 points): Corporate intranet or local workstation.
  - Temporal Risk Add-on:
      * After-hours (before 8 AM or after 7 PM) or Weekends: +5.0 points.
  - Exfiltration Intent Surcharge:
      * NLP intent detection trigger: +25.0 points.

Minimum Risk Floors (Safety Guards):
  - HIGHLY_CONFIDENTIAL or Credentials detected: Risk Floor = 85.0 (CRITICAL -> BLOCK)
  - RESTRICTED or Identity/Financial data detected: Risk Floor = 80.0 (CRITICAL -> BLOCK)
  - CONFIDENTIAL detected: Risk Floor = 60.0 (HIGH -> WARN/BLOCK)
  - INTERNAL detected: Risk Floor = 35.0 (MEDIUM -> WARN)

15. COMPLIANCE, SECURITY HARDENING & DEFENSIVE CONTROLS
================================================================================

1. ZERO WIRE DECRYPTION:
   Inspects files at the source application DOM layer before transmission, avoiding 
   invasive root certificates, MITM latency, and HTTPS decryption liabilities.

   preventing cross-device spoofing or token replay.

   Endpoint agent buffers events in local SQLite during network disruptions, ensuring 
   zero telemetry loss upon reconnection.

4. REAL-TIME CLEAN ALERT BASELINE:
   Alerts and incidents are strictly generated from genuine live endpoint activity 
   (USB copy, cloud upload, clipboard exfiltration), eliminating fake/demo clutter.

   - GDPR Article 32 (Security of Processing & Data Protection)

# Open PowerShell as Administrator:
$Action = New-ScheduledTaskAction `
    -Execute "pythonw.exe" `
    -Argument "`"C:\SentinelDLP\agent\agent.py`" --server `"http://172.24.143.236:8000`" --employee-id `"EMP-001`"" `
    -WorkingDirectory "C:\SentinelDLP\agent"

$Trigger = New-ScheduledTaskTrigger -AtLogon
$Principal = New-ScheduledTaskPrincipal -UserId "$env:USERDOMAIN\$env:USERNAME" -LogonType Interactive -RunLevel Highest
$Settings = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -ExecutionTimeLimit 0 -RestartCount 3 -RestartInterval (New-TimeSpan -Minutes 1)

Register-ScheduledTask -TaskName "SentinelDLPAgent" -Action $Action -Trigger $Trigger -Principal $Principal -Settings $Settings -Description "SentinelDLP Enterprise Endpoint Protection Agent"
Start-ScheduledTask -TaskName "SentinelDLPAgent"
